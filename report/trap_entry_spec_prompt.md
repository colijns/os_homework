## 1. 功能规格

目标文件为 `code/kern/trap/trapentry.S`。框架已经提供 `SAVE_ALL`、`struct trapframe`、`REGBYTES`、`LOAD`、`STORE` 和 `sret` 返回骨架，本次只完成汇编入口与上下文恢复。

### 1.1 RESTORE_ALL

- 输入：`sp` 指向由现有 `SAVE_ALL` 构造、允许 C 层更新的有效 Trap frame。
- 输出：恢复通用寄存器，以及 `sret` 所需的 `sstatus`、`sepc`。
- 布局：通用寄存器位于第 0—31 个槽位，四个状态字段位于第 32—35 个槽位；以实际 `trap.h` 和 `riscv.h` 为准。
- 约束：恢复 `sp` 之前完成其他所有基于当前 Trap frame 的加载；`x0` 无需恢复写入。
- 约束：临时用于读取 CSR 的寄存器仍要从保存区恢复；使用 C 层修改后的保存值，不覆盖为固定返回地址或固定特权级。
- 范围：保存区的 `badvaddr`、`cause` 保留用于诊断；不为了形式上的对称而无依据地回写全部 CSR。

### 1.2 __alltraps

- 先执行现有 `SAVE_ALL`。
- 按调用约定将当前 Trap frame 地址放入第一个参数寄存器。
- 调用签名不变的 `trap(struct trapframe *tf)`。
- C 层返回后，`sp` 仍指向调用前的 Trap frame，执行流进入原有 `__trapret`，恢复现场并执行 `sret`。

## 4. 实际修改、问题与调整

| 问题或调整 | 观察与处理 |
| --- | --- |
| 生产实现 | 在 `RESTORE_ALL` 恢复两个返回 CSR 和可写 GPR，最后恢复 `sp`；入口增加 `mv a0, sp` 与 `call trap` |
| 旧 CSR 名称不能汇编 | GCC 15.1.0 报告不认识 `sbadaddr`；在文件开头将它映射到框架已有的 `CSR_SBADADDR`，保留 `SAVE_ALL` 内容 |
| 原工程缺少中断、异常处理函数 | 基线与修改后完整构建均在相同两个函数处失败；保留日志，正式 `trap.c` 未改 |
| 继承的 Best-Fit 文件不完整 | 基线单独编译时报告 `free_list`、`nr_free` 未定义；测试副本跳过 PMM，不越界修复 |
| 初版验证文件同名 | 验证脚本曾将 `.c`、`.S` 都命名为 `a_probe`，导致 Makefile 目标名冲突；改成 `a_probe.c` 与 `a_probe_entry.S` |
| 旧 QEMU 的状态位差异 | 初次运行在 QEMU 4.1.1 因返回后 SPIE 为 0 未通过标准状态检查；查阅对应源码确认差异，最终使用 QEMU 6.2.0 验证 |
| 默认固件未进入内核 | QEMU 6.2.0 默认固件报告下一跳地址为 0；本轮参数下显式使用已有 OpenSBI v0.4 跳转固件后进入内核 |
