## 一、生成 SLUB 实现的提示词

```text
[PROMPT]
任务：在现有 RISC-V uCore Lab2 工程中实现简化 SLUB
对象分配器，并接入内核启动流程。请直接创建和修改工程文件。

先阅读当前 pmm.h、pmm.c、memlayout.h、list.h、init.c 和三个 PMM。
参考 Linux 官方内存分配文档及 mm/slub.c 的核心思想，自行编写适用于
本实验的实现，不把 Linux 内核的依赖、并发和 NUMA 机制搬入教学内核。

[RELY]
1. 队友已实现物理内存初始化、Best-Fit 和 Buddy；默认选用 Buddy。
2. 下层接口为 alloc_pages(n)、free_pages(base,n)、nr_free_pages()。
3. alloc_pages 可能分配不少于 n 页；当前 Buddy 会向上取整到二次幂。
4. 可使用 alloc_page/free_page、page2pa、pa2page、PADDR、va_pa_offset、
   PGSIZE、list_entry_t、memset、assert；KADDR 在当前 pmm.h 中被注释。
5. struct Page 的 flags/property/page_link 属于已有页分配器；不得改变
   Page 布局、三个 PMM 的实现、page_init 或现有页分配器测试。
6. 本实验在单 hart、不可重入的启动环境中运行，不要求 SMP/中断并发。

[GUARANTEE]
创建 kern/mm/slub.h 和 slub.c，对外提供：
    void slub_init(void);
    void *kmalloc(size_t size);
    void kfree(void *ptr);
初始化放在 pmm_init() 成功返回之后。Makefile 已自动收集 kern/mm 的 C 文件。
测试入口单独放到 slub_test.c；init.c 只添加必要的包含和调用。

[SPECIFICATION]
1. 两层架构：底层申请/释放物理页，上层将页拆成多个可复用对象槽位。
2. 小对象使用 16、32、64、128、256、512、1024、2048 字节的缓存。
   请求向上选择能容纳它的类别；返回地址至少 16 字节对齐。
3. 每个 slab 使用一页，管理头放在该页内，空闲对象自身保存下一空闲
   对象指针，不依赖另一个动态分配器来分配管理信息。
4. 维护 partial 链表、空闲对象链和在用计数。满页退出 partial 链表，
   第一个对象被释放后重新加入，最后一个对象被释放后整页归还 PMM。
5. 维护分配位图，检查槽位合法性和仍处于在用状态的对象。
6. 大于 2048 字节的对象走连续页路径。管理头为 16 字节，记录魔数和
   实际申请页数；计算负载加管理头时先防止溢出，申请页数统一向上
   取整为二次幂，并在释放时传回完全相同的页数，兼容三个 PMM。
7. kmalloc(0)、溢出、过大请求和内存不足返回 NULL，失败不消耗页。
   kfree(NULL) 无副作用；其余 kfree 参数必须是尚未释放的原始指针。
8. 返回内存不保证清零；不伪造学号、运行输出或并发安全性结论。
9. 保持物理内存初始化和页分配器文件原样，除 init.c 接入外通过新增文件完成。
```

## 二、生成独立测试的提示词

```text
[PROMPT]
为上述 SLUB 编写独立的内核测试和 Linux/WSL 自动验证入口。
直接修改实际文件。先依据接口和行为规范设计断言，再运行真实 RV64
内核验证；不要通过打印 PASS 代替断言，不用宿主 malloc 或模拟 PMM
替代真实页分配器。

[RELY]
公开接口为 slub_init、kmalloc、kfree 和 PMM 的公开接口。
对象至少 16 字节对齐，小对象类别上界 2048，大对象管理头占 16 字节，
连续页统一取二次幂；空 slab 必须归还所有页。
仅使用公开接口测试，不读取 SLUB 私有结构、位图或缓存数组。

[GUARANTEE]
创建 kern/mm/slub_test.c，提供 void slub_check(void)。
创建 tools/run_slub_checks.py，实际编译并启动 QEMU，保存原始构建日志、
内核输出、版本、源码摘要和结果 JSON；失败或超时必须返回非零。

[SPECIFICATION]
1. 覆盖每个小对象类别边界、非二次幂请求、大对象及跨页请求。
2. 同时保存多个对象，检查至少 16 字节对齐、请求区间互不重叠；写入
   不同的逐字节模式，乱序释放前核对所有请求字节，发现越界覆盖。
3. 验证 32 个 64 字节对象共用一页，而不是每个对象各占一页。
4. 分配足够多的小对象跨越 slab 容量；从先前的满 slab 释放对象，
   再申请相同大小，验证空闲槽位确实被复用。
5. 检查大对象负载加管理头的边界：4080/4081、8176/8177、16368/16369
   字节分别占用 1/2、2/4、4/8 页，释放后计数完全恢复。
6. 覆盖零长度、整数溢出、超出可管理内存的请求和 kfree(NULL)。
7. 使用固定随机种子混合执行 2000 次分配/释放；保存尚在使用对象的
   长度和数据模式，最终释放所有对象，验证空闲页数与开始一致。
8. 实际占住 PMM 的全部剩余页，使 nr_free_pages() 为零；新 slab 和
   大对象分配应失败，但已有 partial slab 内的空闲槽位仍可分配。
   释放全部占用页与对象后，页数必须完全恢复。
9. SLUB 测试后再次调用当前 PMM 原有 check，检查底层状态没有损坏。
10. 在临时副本中分别选择 Buddy、Best-Fit 和 First-Fit，并增加一次
    64 MiB Buddy 测试；不修改提交版本默认的 Buddy 选择。
11. 自动验证必须观察完整成功行和全部八组 PASS，核对前后空闲页数。
    内核最终 while(1)，允许在明确成功之后结束 QEMU；超时不是通过。
12. 可以保存原始提交的基线自检结果；不得把编译、静态审查或指导书
    示例写成已经完成的 QEMU/GDB 动态观察。
```

## 三、实现与测试的对应关系

| 提示词 | 实际文件 | 关注点 |

| 第一份 | `code/kern/mm/slub.h`、`slub.c`，以及 `init.c` 的接入 | 两层分配、地址转换、生命周期、页数对称 |
