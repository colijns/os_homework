# Lab2 C：SLUB 分配算法

团队汇总报告见 [report.md](report.md)，其中 4.2.4 节为 SLUB 实现，5.2—5.4 节为测试与复现。本文件保留 C 部分的详细设计和开发记录。

## 1. 实验目标与代码基础

本部分完成内核内存对象分配器，使内核能够按字节申请和释放不同大小的内存。实现采用两层结构：底层使用已有物理页分配器，上层将物理页划分为多个对象槽位，减少小对象各自占用整页造成的浪费。

代码基于仓库 `lab2` 分支的 [458450e](https://github.com/colijns/os_homework/commit/458450edb61070685462b500a7d49286a6358f7c)。其中物理内存初始化、Best-Fit 和 Buddy 已由组员完成，本部分保留这些实现，默认页分配器仍为 `buddy_fit_pmm_manager`。内核接入只在 `kern/init/init.c` 中增加头文件和两个调用，其余实现与测试均通过新增文件完成。

设计时参考了 Linux 官方[内存分配说明](https://docs.kernel.org/core-api/memory-allocation.html)以及 [SLUB 源码中的空闲对象链和 partial/full 状态说明](https://github.com/torvalds/linux/blob/master/mm/slub.c)。本实验自行编写适用于 uCore 的简化实现，管理信息布局、接口和页数策略均以当前工程为准，没有直接移植 Linux 源文件。资料查阅日期为 2026-10-22。

本部分的规格重点是：在物理内存初始化之后提供对象级接口；成功时返回至少 16 字节对齐、互不重叠的内存；失败时返回空指针且不消耗物理页；释放全部对象后，空闲页数恢复到测试前的值。两份实现与测试提示词见 [slub_prompt.md](slub_prompt.md)。

## 2. 整体逻辑与接口

启动时先执行原有 `pmm_init()`，完成物理内存探测和页分配器检查；再执行 `slub_init()` 初始化对象缓存，最后运行 `slub_check()` 验证对象分配行为。

```text
kern_init()
  ├─ pmm_init()                   组员 A/B 已有实现与自检
  ├─ slub_init()                  初始化八个对象缓存
  └─ slub_check()                 独立测试与底层页分配器复查

kmalloc(size)
  ├─ 1..2048 字节：大小类别 → partial slab → 一个对象槽位
  └─ 更大请求：负载 + 管理头 → 连续物理页

kfree(ptr)
  ├─ 小对象：归还槽位；最后一个对象释放时归还整个 slab 页
  └─ 大对象：取出记录的实际页数，归还整块连续页
```

| 接口 | 前置条件与行为 |
| --- | --- |
| `slub_init()` | 在 `pmm_init()` 后调用一次，初始化静态缓存，不申请对象页 |
| `kmalloc(size)` | 初始化完成；返回未清零的内存，至少 16 字节对齐；零长度、过大、溢出或无可用空间时返回 `NULL` |
| `kfree(ptr)` | `NULL` 无副作用；其余参数应为尚未释放的原始对象指针，无须再提供长度 |
| `slub_check()` | 单 hart 启动阶段运行；通过断言检查功能，全部完成后输出成功行 |

## 3. 核心数据结构与实现

### 3.1 按大小组织对象缓存

小对象分为 16、32、64、128、256、512、1024、2048 字节八个类别。例如，申请 23 字节时选择 32 字节类别。调用者可以请求非二次幂长度，类别向上取整的差额属于内部碎片。

每个 `slub_cache` 保存该类别的对象大小和 partial 链表。每个 slab 使用一个物理页，页头的 `slub_slab` 保存所属缓存、链表节点、空闲对象链、在用对象数、容量和分配位图。页头之后按 16 字节对齐，再排列对象槽位。

管理信息直接放在申请到的页内，避免初始化分配器时还依赖另一个动态分配器。空闲对象的第一个机器字存放下一空闲对象的地址；对象分配给调用者后，这部分空间可以正常写入数据。

### 3.2 小对象的申请与回收

`kmalloc()` 先选择能容纳请求的最小类别。如果 partial 链表为空，`new_slab()` 调用 `alloc_page()` 取得一页，建立页头和空闲对象链；否则复用已有 slab。随后从空闲链取出一个槽位，设置其分配位图并增加在用计数。

当 slab 的最后一个空闲槽位被分配后，该页已满，会退出 partial 链表。从满 slab 释放第一个对象时，重新把该页加入 partial 链表；释放最后一个在用对象时，摘除链表节点并将整页交还给 `free_page()`。因此，空 slab 不会长期占用底层物理页。

`kfree()` 通过对象地址按页向下对齐定位页头，核对魔数、槽位边界和分配位图，再完成释放。调用约定要求传入原始有效指针；断言检查用于发现明显的错误调用，不提供任意无效指针或已复用地址的完整诊断能力。

### 3.3 大对象与 Buddy 的接口匹配

大于 2048 字节的请求使用连续页。大对象管理头占 16 字节，记录魔数和实际申请页数，返回地址位于管理头之后。

设请求长度为 `size`：

```text
needed = ceil((size + 16) / 4096)
npages = 不小于 needed 的最小二次幂
```

计算时先检查加法溢出，再使用除法和余数计算所需页数。这样不需要在可能接近整数上界的长度上直接执行一般的向上对齐加法。

当前 Buddy 会将页数向上取整，因此本实现统一向所有后端申请二次幂页数，并在管理头保存相同的 `npages`，释放时原样传给 `free_pages()`。例如，8192 字节负载加上管理头需要三页，实际申请并释放四页。这个约定也能直接用于 First-Fit 和 Best-Fit。

### 3.4 地址转换和原有代码的关系

`alloc_pages()` 返回 `struct Page *`，不是可以直接写入的内核对象地址。实现使用 `page2pa(page) + va_pa_offset` 得到内核虚拟地址；释放时用 `PADDR()` 和 `pa2page()` 找回页描述符。当前 `pmm.h` 中 `KADDR` 被注释，因此没有依赖该宏。

SLUB 不复用或改写 `Page` 的 `flags`、`property`、`page_link`，这些字段继续由原有页分配器管理。三种页分配器的选择只发生在自动测试的临时副本中，提交工作目录的默认选择仍为 Buddy。

## 4. 测试设计与实际结果

测试文件只调用 SLUB 和 PMM 的公开接口，不读取 SLUB 私有结构。测试采用逐字节数据模式、地址区间检查和物理页计数，分别检查数据正确性、对象隔离性和资源回收情况。

| 组号 | 测试内容 | 能检验的问题 |
| --- | --- | --- |
| 1 | 各类别边界、非二次幂和跨页请求，同时保存多个对象 | 对齐错误、空间不足、地址重叠及数据覆盖 |
| 2 | 同时申请 32 个 64 字节对象，只减少一页 | 小对象是否真正共享 slab 页 |
| 3 | 申请 300 个小对象，跨越 slab 容量，释放满页中的对象后再次申请，乱序回收 | 新 slab 扩展、full→partial 转换与空闲槽位复用 |
| 4 | 管理头边界及多轮大对象释放 | 连续页取整和实际释放页数是否一致 |
| 5 | 零长度、整数上界、过大请求和 `kfree(NULL)` | 边界输入是否消耗或破坏页资源 |
| 6 | 固定种子下混合执行 2000 次对象分配与释放 | 不同生命周期、大小混合时的数据隔离与回收 |
| 7 | 实际占住全部剩余物理页，再申请新 slab、大对象和已有缓存对象 | 真实 OOM 返回、已有空闲槽位复用及耗尽后的恢复 |
| 8 | 再次运行当前页分配器原有 `check()`，核对前后总页数 | 底层空闲块状态是否损坏、是否发生页泄漏 |

第 4 组还明确验证了包含管理头的临界点：4080/4081 字节分别使用 1/2 页，8176/8177 使用 2/4 页，16368/16369 使用 4/8 页。每次释放后都重新核对空闲页数。

## 5. AI 使用过程与问题处理

开发采用两份分开的提示词：第一份明确接口、数据结构、生命周期和与 Buddy 的页数约定；第二份依据行为规格生成独立测试。完整内容和文件对应关系保存在 [slub_prompt.md](slub_prompt.md)。

过程中处理了以下问题：

1. **Windows/WSL 路径兼容。** Windows 创建的独立工作目录使用了 Windows 形式的 Git 路径，WSL 最初无法读取。调整该目录的相对指向，并在验证器中显式指定工作目录后，基线与工作版本都能正常读取。编译仍使用本机已有的交叉工具链。
2. **日志结束过早。** 首版验证器在看到成功标记前缀后立即结束 QEMU，曾截断输出中的最终页数。验证器改为等待整行结束，同时检查八组 PASS 和前后页数一致，之后重新执行全部最终测试。
3. **边界覆盖不足。** 静态复核未发现阻断问题，但指出仅围绕 4096、8192 字节负载测试，不能直接覆盖额外 16 字节头造成的页数临界点。因此增加三对明确边界输入及占用页数断言，再次完成全部验证。

这些调整分别涉及环境路径、证据采集和测试覆盖。本次动态验证没有记录到 SLUB 功能断言失败，报告不虚构算法错误或问答过程。

## 6. 与操作系统原理的联系

页分配器解决连续物理页的组织、分配与合并，SLUB 在此基础上处理更细粒度的内核对象。两者分工不同，但通过申请和归还页形成上下层关系。小对象共享页能够降低浪费，大小类别的向上取整仍然会产生内部碎片；整页归还后能否组成更大的连续块，由底层页分配器决定。

本实验体现了对象缓存、空闲链、状态转换和资源计数不变量。运行范围是单 hart、非重入的内核启动阶段，结构和接口采用教学规模；并发锁、每 CPU 缓存、NUMA 和完整的通用类型缓存管理没有在本部分展开。虚拟内存换页、进程地址空间和页面置换也是本部分未实现的 OS 知识点。
